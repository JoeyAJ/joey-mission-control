The existing onboarding feature saves private session/cloud drafts, checks a read-only creation plan and exports a six-file JSON packet. No idea or acceptance text is replaced with an invented summary.

The preparation is bound to the saved draft ID/revision, current plan, private target and source branch. Expired or conflicting plans, mismatched targets/revisions and altered instructions cannot produce a usable delivery. Dirty edits, changed selection, capability expiry or access revocation clear the prepared delivery. Existing current Owner/AAL2 checks, cloud CAS/conflict/lost-response reconciliation and same-origin transport remain in their existing controller. Preparing a package does not save it to cloud; the UI separately shows session-only versus confirmed cloud revision.

The package is `PRIVATE_OFFLINE_PACKAGE_NOT_PROVISIONED`; repository creation, registry registration and Agent startup remain false. It requests private visibility and exact source/report scopes without granting them. `mc/progress` stays a report-only branch with deployments disabled. Existing-project/repository/branch/Preview conflicts remain blocked. A missing repo remains unspecified or a labelled derived proposal, never an existence/privacy/access receipt. The receiving Agent is instructed to preserve the complete PRD, use only existing explicit authority, continue independently authorized work and return real actor/HEAD/files/tests/blockers/receipts. There is no automatic dispatch or one-click execution claim.

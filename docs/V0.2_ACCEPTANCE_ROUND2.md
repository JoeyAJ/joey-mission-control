## Joey 決策語意
四類分開：明確 Joey 批准／決策、阻礙、缺失／未驗證資料、來源明確記錄的無需行動。

批准／決策必须有 canonical claim、可追溯來源與 SHA256 fingerprint，以及已讀取的 documented／verified 來源狀態。documented 表示來源文件已記錄該要求，不代表工作已通過測試或 Joey 驗收。決策來源章節 `Decisions Needed From Joey` 可提供明確 Joey 責任上下文；缺失、否定、已批准或延後決定文字不能只靠章節名稱轉成待辦。

未記錄任務、Agent、模型、下一步、最近完成或來源缺失不會產生 Joey 決策。僅禁止執行的文字維持限制／blocker，不能授予執行權限，也不自動要求 Joey 現在批准。無已校對摘要仍是摘要缺失，不能變成人工批准。

測試涵蓋 `No Joey approval is needed`、`Joey approval is unnecessary`、`Joey is not required to approve`、已收到 confirmation、待驗證 approval；也保留 `Joey must choose one of the approved providers` 等真實選項決策。

Dashboard、Project Detail、Attention 的 indicator／計數共用相同判斷。Inbox 仍是本機提案工作流，使用其原有 Needs review／Ready to confirm／In progress／Resolved，不能成為 canonical decision、project completion 或 Acceptance 更新。

## Workspace 安全 invariant

Workspace Assignment → Agent Work → Evidence / Artifact → Test / Verification → Handoff → Acceptance / Approved State → Canonical State Update

Workspace assignment 僅記錄工作意圖／執行情境。既有 SessionService 的可編輯欄位是本機 ai、model、workspaceId、path、repository、branch、commits、permissionBoundary、declaredTask；狀態僅 starting／running／waiting_for_joey／stopped／failed。`waiting_for_joey` 是本機工作階段聲明，不能單獨建立 canonical Joey decision。

建立／編輯 session 只更新安全分離的本機 `sessions.v1.json`；沒有 canonical 寫入器，無完成、驗收、verified Agent／Model history 的寫入欄位。現有實作已尊重此邊界，因此未改寫 SessionService 或架構。新增測試比對建立／編輯／狀態切換前後 canonical status、phase、stage、mission、lastCompleted、Agent、Model、fingerprints 與完整 Handoff；僅忽略每次讀取新產生的 readAt。非法完成／驗收／history欄位被拒絕。UI 另加簡短說明。

Canonical 更新必須經外部 gatekeeper 的完整證據與批准鏈；本機表單沒有實作自動 promotion。

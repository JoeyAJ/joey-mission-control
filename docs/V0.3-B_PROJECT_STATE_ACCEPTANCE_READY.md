## 3. Architecture changes

單一 canonical state 存在原有 owner store 的 `owner.canonicalState`。`ProjectStateRepository` 與舊 owner approval 使用同一個 JsonStore、檔案鎖、版本號與原子交易。首次 GET 只做唯讀遷移；首次成功 mutation 才保存 canonical state。

`public/project-state.js` 同時供 server tests 與瀏覽器使用，是唯一 pure derivation engine。Joey View 的 Current Phase、Blueprint、Next Waypoint、Mission Path、Project Status、Decision Center 與生命週期看板取自同一份 state，沒有獨立保存衍生值。

`GET /api/projects/:id/project-state` 讀取；`POST` 接受受控 command。保存成功後更新 manifest 的 canonical state，再統一重新推導與呈現，沒有 page reload。展開中的主要編輯區保留；新增 Idea 成功後顯示 Idea 清單。

## 4. Canonical Project State schema

正式契約：`schemas/canonical-project-state.schema.json`；TypeScript 宣告：`src/project-state/types.d.ts`；執行期驗證：`src/project-state/model.mjs`。

Project 包含 schemaVersion、id、name、identity、missionStatement、lifecycle、missions、decisions、ideas、nextActions、sources、metadata，另外有 confirmationQueue、auditLog、provenance。全部 status 使用 enum，顯示文字在繁中／英文／韓文 localization layer。

Mission 包含 projectId、order、dependencies、sourceRefs、createdAt、updatedAt、kind 與 linkedIdeaId。Decision 保留 options、selectedOption、Joey response、resolvedAt，僅顯式 `blocksMission` 才影響有效等待狀態。Idea 保留 source JOEY 與 linkedMissionId。SourceRef 保留 type、label、uri、commitSha、fingerprint、timestamp、verificationStatus、kind。

驗證拒絕額外欄位、跨專案 entity、不存在的 source/link、重複 ID、非法日期、非整數版本與循環任務依賴。

## 5. Derivation rules

- Current：IN_PROGRESS → BLOCKED → WAITING → WAITING_JOEY → 第一個 NOT_STARTED。UNKNOWN 不當成 NOT_STARTED；全部 COMPLETED 顯示任務航線完成，不自動完成 lifecycle。
- Blueprint：從 missions 計算 total、completed、inProgress、waiting、blocked、notStarted、paused、unknown。只有完整任務範圍已確認、非空且沒有 UNKNOWN 時，才計算 `round(completed / total × 100)`。否則顯示資料不完整。
- Next：Joey-confirmed OPEN nextAction → current mission 未完成 dependency → 第一個 NOT_STARTED → OPEN Decision → UNKNOWN。
- Pending Decision：只有 canonical Decision.status=OPEN。Confirmation 與舊版問題不列入。
- OPEN、顯式 blocking Decision 可把可執行任務的有效顯示狀態推導為 WAITING_JOEY；不覆寫 raw mission status。Resolve／defer／cancel 後重新推導，沒有自動完成任務。

衍生輸出標示 SYSTEM_DERIVED；UI 在儀表顯示系統推導或 Joey 已確認輸入。來源事實、Joey 輸入、未知資訊保持分開。

- 任務完成是 Joey 的本機狀態聲明，不自動驗證 GitHub、production、Agent execution；Source／USER_INPUT 明確保留這個差別。
- 已保存 canonical state 不會被後續外部來源更新自動覆寫；外部 source reconciliation／sync 留待後續。
- 最小 Idea UI 支援新增與轉換；完整 review/planning/dismiss 流程、任務 dependency 編輯與複雜 admin UI 尚未提供。
- 單一瀏覽器操作即時更新；其他 tab 使用 CAS 防覆寫，需重新讀取，不提供跨tab即時廣播。
- 舊 feature 權重、proof-driven blueprint proposals 保留於相容 owner layer。新的 Joey View 比例是任務等權比例；舊版 BLUEPRINT 明確批准會替換對應任務、保留 Idea 建立的任務，非法 dangling links 會拒絕交易。

# MC private continuity schema design

NOT APPLIED. No DB/Auth/resource exists from this work. This is a reviewable table/RPC contract, not a migration. Create migrations with the current supported CLI only after authorized project/local SQL verification; no invented migration timestamp. Required live validation remains UNRUN.

| Private table | Primary key / fields | Authority and retention |
|---|---|---|
| mc_private.members | auth user UUID + project ID; roleOWNER/WRITER; active flag; grant revision | Bootstrap admin only; clients cannot self-grant. Exactly one Joey owner and one scoped writer |
| mc_private.heads | project ID; authority epoch; baselineSHA; revision; capacity | Locked by append transaction only; defaults10000events. No client patch/delete; admin cutover changes epoch |
| mc_private.contexts | project ID + context hash; allowlisted Claim JSON; source versions and private evidence hashes | Initial exact filtered import; each <=64KiB, no raw source/log/path; imported data keeps its source qualification |
| mc_private.events | project + epoch + revision; unique operation ID; canonical operation digest; immutable authenticated submitter UUID/role/AAL; server timestamp; typed payload | Append-only; <=8KiB event; bounded10000events/100MiB, never truncation. Result records self-attestation; Joey decision binds result/acceptance/context/baseline and revision |
| mc_private.checkpoints | project + epoch + revision + hash; verified export receipt/backup health | Verified pinned hash stored separately from export bytes; client cannot mark backup verified |

RLS enabled on all private tables; schema is not exposed to Data API. No PUBLIC/anon table privileges or RPC execute. Exposed mc_api RPC only: read_scoped_context(project,afterRevision,limit<=100), append_operation(exact operation), export_checkpoint(project,epoch,revision). No path/ref/SQL/actor/role/time selectors. Provider validates JWT; RPC checks immutable auth.uid(), current membership and auth.sessions session_id. All decisions additionally require aal2. No user_metadata authorization, bypass key, broad database credential or raw table update endpoint.

Append transaction order: authorize current session/member/project first; lock project head; require epoch/baseline; enforce owner+AAL for decisions; match prior idempotency digest+subject; otherwise CAS expectedRevision; allowlist payload and capacity; resolve exact proposal/context hash/acceptance hash, expiry and latest result; append using server subject/time; update head; return immutable receipt. Replays after membership/session revocation refuse, even if previous receipt exists. SQL canonical hashing must be specified and matched against test vectors before cutover; JavaScript key sorting is an offline oracle, not assumed equal to jsonb::text. RPC transaction serialization/concurrency must be proven on real Postgres. SQL permissions must survive Data API exposure changes.

Offline: private-continuity.mjs is a pure Node design oracle; no adapter, SQL, DB, JWT verifier or HTTP endpoint imports it. Branded deeply frozen states prevent arbitrary parsed JSON becoming accepted state. restoreContinuity requires separately pinned checkpoint hash and semantic replay of every receipt including role/AAL/revision/idempotency/proposal/decision. Hash is integrity only; its trusted source/authenticity must be established outside the oracle through verified cloud receipt or owner checkpoint. It cannot authenticate a hash supplied by the same untrusted file. Never translate a restored historical OWNER_ACCEPTED record into permission to execute.

private-continuity-operation.schema.json describes strict typed operations. Additional runtime constraints:8KiB event, expiry<=24hours, current server clock, auth/session/role, CAS, latest-result binding, queue capacity256. Schema alone does not enforce auth or transaction ordering. Pending offline decisions stay drafts; queue never stores passwords/tokens or creates authority. Every enqueue validates existing entries; no changed ID replay or duplicate-corrupted queue.

Live gates after approval: anon/unknown/worker/owner+MFA RLS and execute privileges; explicit disable signup; worker revoke/session logout despite cached JWT; stale/parallel append with database lock; failure atomicity; restart/import/export/hash vectors; backup freshness; two-device current-state owner review; no public/private cross-cache or exposure. No hosted PASS claimed by offline tests.

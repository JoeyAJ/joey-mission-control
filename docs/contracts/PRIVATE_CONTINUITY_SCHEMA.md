RLS enabled on all private tables; schema is not exposed to Data API. No PUBLIC/anon table privileges or RPC execute. Prepared mc_api RPC only: read_events(project,afterRevision,limit<=100), read_context(project,exactHash), append_operation(exact operation). Export_checkpoint remains future work; no RPC is currently granted to an app. No path/ref/SQL/actor/role/time selectors. Future verified provider bridge checks immutable subject, current session and AAL; current_actor() deliberately raises AUTH_BRIDGE_NOT_INSTALLED. No Supabase-specific auth.uid()/auth.sessions dependency is implemented. All decisions additionally require aal2. No user_metadata authorization, bypass key, broad database credential or raw table update endpoint.

Append transaction order: authorize current session/member/project first; lock shared storage budget then project head; recheck session/member after lock wait; require epoch/baseline; enforce owner+AAL for decisions; match prior idempotency digest+subject; otherwise CAS expectedRevision; allowlist payload and capacity; resolve exact proposal/context hash/acceptance hash, expiry and latest result; append using server subject/time; update head; return immutable receipt. Replays after membership/session revocation refuse, even if previous receipt exists. SQL canonical hashing must be specified and matched against test vectors before cutover; JavaScript key sorting is an offline oracle, not assumed equal to jsonb::text. RPC transaction serialization/concurrency must be proven on real Postgres. SQL permissions must survive Data API exposure changes.

Offline: private-continuity.mjs is a pure Node design oracle; no DB/JWT/HTTP activation. Private provider-neutral repository/query ports now import it for isolated local synthetic tests; public code never imports it. Branded deeply frozen states prevent arbitrary parsed JSON becoming accepted state. restoreContinuity requires separately pinned checkpoint hash and semantic replay of every receipt including role/AAL/revision/idempotency/proposal/decision. Hash is integrity only; its trusted source/authenticity must be established outside the oracle through verified cloud receipt or owner checkpoint. It cannot authenticate a hash supplied by the same untrusted file. Never translate a restored historical OWNER_ACCEPTED record into permission to execute.

private-continuity-operation.schema.json describes strict typed operations. Additional runtime constraints:8KiB event, expiry<=24hours, current server clock, auth/session/role, CAS, latest-result binding, queue capacity256. Schema alone does not enforce auth or transaction ordering. Pending offline decisions stay drafts; queue never stores passwords/tokens or creates authority. Every enqueue validates existing entries; no changed ID replay or duplicate-corrupted queue.

Live gates after approval: anon/unknown/worker/owner+MFA RLS and execute privileges; explicit disable signup; worker revoke/session logout despite cached JWT; stale/parallel append with database lock; failure atomicity; restart/import/export/hash vectors; backup freshness; two-device current-state owner review; no public/private cross-cache or exposure.

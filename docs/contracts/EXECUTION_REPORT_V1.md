# Offline execution-report contract implementation

`execution-report.mjs` implements the selected pure P2A subset; it is excluded with `docs` from deployment and imported only by authored synthetic tests. No application/server/UI import, IO, ambient clock, token handling, endpoint, producer hook, writer, execution or dispatch exists. P2A ingress and P2B real producer remain unimplemented. Main Workspace runtime remains disconnected.

Exports: `emptyReportState()`, `reduceExecutionReport(previous, report, context, receivedAt)`, `restoreReportState(snapshot, context)`, `inspectExecutionReports(snapshot, context, readAt)`. All times are supplied explicitly; accepted snapshots are copied and deeply frozen. Rejection returns the original state without mutation and a bounded error code. Restore validates full acceptance history and does not establish custody or authenticate a producer.

Envelope exact fields: schemaVersion `mc.execution-report.v1`; eventId, projectId, missionId, baselineSha, sourceId, sourceRevision, bindingId, sessionId, sequence, expectedRevision, eventAt, issuedAt, expiresAt, kind, model, evidenceId. Model is nullable; non-null model is only a bounded declared identifier, never verified model execution. Evidence is nullable or an ID from the caller-provided authoritative context, not a file/path/log payload. Unknown fields are rejected. Inputs must be plain JSON data: custom serialization/prototypes, accessors, hidden/symbol properties, cycles, array holes and undefined are refused before serialization; accepted duplicate replays also return an immutable copy. IDs are bounded ASCII identifiers, baseline is lowercase40hex SHA, sequence/revision safe integers. This contract is not the downloaded Mac filtered-context schema.

Context explicitly selects one task/source/baseline, allowlisted binding/session pairs and evidence IDs, maximum source-event age, maximum validity and history capacity. The caller must supply that context from real authority after P0 cutover; synthetic fixture context proves no real authority. Synthetic policy has zero future-clock tolerance; production timing policy is unresolved. Hard contract bounds: at most100 sessions,1000 evidence IDs/history entries,24h age/validity. These are safety ceilings, not approved real runtime TTLs.

Rules: exact tuple match; first event per session started/sequence1; subsequent contiguous sequence plus expected revision; identical event replay does not increment revision or renew expiry; changed duplicate bytes conflict. UTC timestamps must be valid calendar times, event≤issued≤received, event age within configured bound, received<expiry and expiry-issued within bound. Source event and acceptance time never regress. Permission-needed grants nothing. Completed/failed/disconnected close that session only. Expired or closed session cannot resume; a new allowlisted session must start. Another session cannot displace an active unexpired report. At history capacity, refuse new reports instead of discarding dedupe evidence or silently creating a store.

Inspection keeps full historical acceptance records separate from the latest **reported** record. It exposes reported-window/expired/closed, never process-live state. `runtimeConnected:false`, currentAgent/currentTask:null, `CALLER_DECLARED_IDENTITY_NOT_VERIFIED`, `PRODUCER_ATTESTATION_NOT_PROCESS_OBSERVATION`, owner acceptance `NOT_INFERRED` are unconditional. A legitimate token holder could impersonate an allowlisted binding; this layer has no token or emitter observer and cannot upgrade identity evidence.

Verification: `tests/execution-report.test.mjs` uses only labeled synthetic fixtures. Covers task/source/session binding, nullable model, payload rejection, CAS/sequence/idempotency/conflict, freshness, lifecycle/recovery, identity impersonation, immutable restore, replay without freshening, history capacity, chronological regression, no application wiring and actual production adapter GET404/non-GET403. Real source readback, real producer end-to-end, ingress/restart persistence and deployed browser are NOT RUN for this stage. Prior unchanged UI QA remains evidence of P1 only. Activation dependencies remain in `../MC_EXECUTION_REPORT_PROPOSAL.md`.

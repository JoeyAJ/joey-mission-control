# Repository run v2 — reported delivery evidence

Supported versions are mc.repository-run.v1 and mc.repository-run.v2. v1 remains the helper default; no v1 field is relaxed or rewritten. v2 requires header taskKind (FEATURE, BUGFIX, DOCUMENTATION or DELIVERY_FOLLOWUP) and each event.delivery (null or a snapshot). Existing lifecycle, 16 KiB file / 64 events / 20 runs limits, registration/source binding, result and terminal immutability apply unchanged. Unknown fields/versions reject. New helper event input is bounded at 8 KiB, report bound unchanged.

A snapshot contains exactly qualification=AGENT_REPORTED, scope, deployment, verification, handoff, data. scope repeats exact report projectId/track/repositoryId/runId/taskId/workRef and full codeSha; completed result codeSha must agree.

| Section | Fields | Completion requirements |
|---|---|---|
| deployment | status, target, id, deployedSha, url, observedAt, evidence, notRequired | READY requires permitted target, deployment ID, deployedSha=codeSha, exact permitted HTTPS URL, actual observation time and evidence. PENDING/FAILED remain incomplete. NOT_RECORDED has null fields. |
| verification | status, method, checkedAt, deploymentId, checkedSha, url, evidence, notRequired | PASS requires exact deployment ID/URL/code SHA and actual functional method/time/evidence after deployment observation. BLOCKED has checkedSha=null because served bytes were not verified. FAIL/BLOCKED or SYNTHETIC_FIXTURE do not establish delivery ready. |
| handoff | status, path, commitSha, checkedAt, evidence | CURRENT requires an allowed canonical handoff/context path and exact commit/time/evidence; completed result handoff pointer must match. STALE/NOT_RECORDED is incomplete. |
| data | status, version, checkedAt, evidence, notRequired | APPLIED needs recorded version/time/evidence. PENDING/FAILED/NOT_RECORDED is incomplete. NOT_REQUIRED needs policy/reason/time. |

All fields are required, with explicit null when unrecorded. Deployment states: NOT_RECORDED/PENDING/READY/FAILED/NOT_REQUIRED. Verification: NOT_RECORDED/PASS/FAIL/BLOCKED/NOT_REQUIRED; method HTTP_FUNCTIONAL_CHECK/BROWSER/OWNER_DEVICE/SYNTHETIC_FIXTURE. Handoff: NOT_RECORDED/CURRENT/STALE. Data: NOT_RECORDED/PENDING/APPLIED/FAILED/NOT_REQUIRED. Times must be strict ISO and no later than their event. Plain bounded text cannot contain credentials/trusted-claim markers. target has provider/project/environment. IDs, hashes, URL and scope must agree; URL username/password/query/hash and foreign/unpermitted target reject. No URL is fetched by validator/helper/reader/rendering.

Parity tests cover shared structural/static constraints and demonstrate code rejection of schema-valid semantic conflicts. Old reports are not converted or rewritten.

Derived delivery reported ready requires run completed, all reported tests PASS, deployment READY or applicable N/A, actual functional PASS or applicable N/A, handoff CURRENT, and data APPLIED or reasoned N/A. Run completed alone never establishes delivery. Independent verification and Joey acceptance remain pending. MC Contents-read proves report blob integrity/scope only. No trusted observation path is added; caller MC_VERIFIED/unknown attestation is rejected. Provider metadata and served functional results are separate Agent-reported claims.

Each event is a dated snapshot. A later null or changed-code snapshot withdraws prior evidence; it cannot reuse old deployment/functional proof. Fixed alias movement does not update historical evidence. Terminal reports remain immutable; followup uses a new same-scope run with predecessorRunId. Existing historical bytes are never upgraded to v2.

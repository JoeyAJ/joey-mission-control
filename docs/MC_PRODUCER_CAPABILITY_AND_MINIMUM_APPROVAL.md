## Recommended minimum, without a new private backend or Auth service

Use one next **already-approved Codex CLI task** on an existing authorized executor. Parent chooses the existing project/mission/baseline and runtime; Joey need not design an API. A bounded local observer consumes that invocation's JSONL stdout, with producer identity derived from the actual child-process/session transport, not a caller-entered name. Preserve source timestamp if present; otherwise leave it null and label observer received time separately. Filter immediately to IDs, lifecycle status, sequence, source revision/baseline and safe evidence IDs; discard prompts, message bodies, code, commands, paths and raw outputs instead of storing or transmitting them. Nullable model stays unknown if unsupported. A new session is not automatically permission to run another task.

After authority review, integrate with the existing MC loopback service and existing configured private data root. Recommended bounded store: `execution-reports.v1.json` under that root (`config.dataRoot`), with the selected observer as the only writer, at most1000 receipts, atomic/CAS updates, no overwrite/truncation at capacity, and an immutable rollback checkpoint. Existing owner/inbox/canonical stores remain authoritative and read-only. Reuse existing local access boundaries only if verified available; no new credential is created. Shared-token callers remain self-attested; only an actual verified transport may strengthen emitter evidence. Public MC remains fixed safe snapshots; no private report GET or write is added to production.

Exact approval packet for parent to prepare once:
